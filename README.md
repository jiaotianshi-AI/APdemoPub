# APdemo —— AP 自学网站（演示版）

中英双语的 AP 自学网站。进度和测试为核心主模块，自学视频 / AP 问答机器人为辅助模块，页面底部为“关联网站”链接。
**现在需要登录才能访问任何页面**，有三类页面：

| 地址 | 谁用 | 说明 |
|---|---|---|
| `/apdemo` | 学生（AP 自学板块） | 学生页：显示自己最近一场测试的科目、单元、时间、倒计时和学习进度；“所有测试”列表；“立即测试” |
| `/apdemo/exam?id=…` | 学生（AP 自学板块） | 测试页：选择作答方式、倒计时、看题和作答、提交；测试完成后回顾 |
| `/supervisor` | 督导者（家长/老师） | 为关联的学生新建测试（可多选学生）、上传题目 PDF、修改/删除待测试、上传答题 PDF 与录入分数、重测 |
| `/admin` | 管理员 | 账号管理：新建、编辑关联、停用/启用、重置密码、删除 |
| `/admin/ai` | 管理员 | AI 评分设置：模型、API 密钥（可测试连通性）、判分系统提示语（可编辑） |

账号类型：学生、督导者、客服、管理员。客服登录后暂时只看到“暂未开放”。最终报告见 `REPORT.md`。

## 目录
```
index.html            学生页
pages/                登录、修改密码、管理员、督导者、客服占位页
assets/css, js, img   前端资源（auth.css / admin.css / admin.js 等为账号相关页面）
data/                 内容数据 + schema/（学生页使用，登录后才能读取）
server/               Node.js 后台（登录、会话、账号管理接口、命令行工具）
deploy/               Caddy 配置、systemd 服务、安装/更新/备份脚本
docs/                 DATA_MODEL.md、API.md
tests/                Playwright 测试与截图
```
后台只用 Node.js 自带功能（`node:sqlite`、`crypto`、`http`），运行时 npm 依赖只有一个：`unpdf`（把 PDF 里的文字提取出来，给 DeepSeek 等只能读文字的 AI 模型用）；服务器上更新时 `deploy/update.sh` 会自动执行 `npm ci --omit=dev` 安装它；需要 Node.js 22.13 或更高。

## 本地运行
```bash
export COOKIE_SECURE=0                 # 本地是 http，不是 https，需要关掉 cookie 的 Secure 属性（仅本地）
node --disable-warning=ExperimentalWarning server/cli.js create-admin 你的管理员账号名   # 会打印一次性初始密码
npm start                              # 然后访问 http://localhost:3000/
```
数据库默认在 `var/apdemo.db`（已加入 `.gitignore`，不会被提交）。用 `APDEMO_DB=路径` 指定别处。
首次用管理员登录会要求先修改初始密码，然后进入 `/admin`。

## 测试规则
**督导者页面（`/supervisor`）**
- **新建测试**：目标学生（可多选，含“所有学生”）、测试日期和时间（按**学生所在时区**）、测试时长（5–300 分钟，默认 60）、本单元开始学习日期、测试科目、测试单元、题目 PDF（可多个，**每个 PDF 是一道题**，按上传顺序编号）。每个被选中的学生各生成一条独立的测试记录。
- 状态：**待测试 → 测试中 → 已提交（待评分）→ 已评分**。
- **每道题**有：题号（Q1、Q2…，按上传顺序）、问题 PDF、**权重**（1–100 的整数，默认 1，由家长/老师在新建或修改测试时设定，评分后也可以调整）、**回答文字**（学生用屏幕输入作答时自动带出，纸质作答为空）、回答 PDF（扫描件，可为空）、评分（1–5，可为空）。
- **汇总评分** = 各题评分的**加权平均值**，四舍五入到整数（x.5 进位）：加权平均 = Σ（权重 × 评分）÷ Σ权重；**每道题都评完**才计算，并且状态自动变为“已评分”；任何一题评分为空则汇总为空。所有题权重相同（默认都是 1）时就是普通平均。例：Q1=5(权重 1)、Q2=3(权重 2)、Q3=4(权重 1) → (5+6+4)÷4 = 3.75 → 汇总 4。公式只在 `server/scoring.js` 一处，要改公式改那里并同步 `assets/js/supervisor.js` 里的说明文字（`FORMULA_TEXT`）和预览（`summarizeScores`）。
- **待测试**：可以修改、删除；也可以直接为每道题上传回答 PDF、评分（学生不通过网页作答时用）。**测试中**：不能修改，只能查看。**已提交**：查看学生答题、为每道题上传回答 PDF 并评分。**已评分**：查看学生答题、修改每题的评分和回答 PDF、**重测**（复制科目、单元、时长、题目文件和每题权重，重新设定时间，生成一条新的“待测试”记录；原记录和分数保留）。
- **查看学生答题**：每道题的文字答案、作答方式、开始/提交时间、是否到时自动提交、离开页面的次数和时长。每道题和整次测试各有“请求 AI 评分”按钮——**接口已预留，目前提示“尚未开放”**。
- 以后 AI 评分写入同一套每题评分字段。
- 督导者页的“过往的测试”同样默认折叠（只显示测试时间、科目单元、评分），点一下展开完整信息和操作按钮，也可以“全部展开/全部收起”；展开状态在保存评分等操作后保持。
- 督导者只能看到和操作自己关联的学生；PDF 不能通过网址直接访问，每次打开都检查登录和权限。

**学生页（`/apdemo`、`/apdemo/exam`）**（旧网址 `/`、`/exam` 会自动跳转）
- “进度和测试”卡片显示**排期最近的一场**：科目、单元、时间、倒计时；学习进度 = 从“本单元开始学习日期”到测试时间已走过的比例。
- **所有测试**：列出自己的全部测试。**未完成的测试看不到题目**，学生**不能修改**任何内容。**已评分的过往测试默认折叠**，只显示测试时间、科目单元、评分；点一下展开显示完整信息，也可以“全部展开/全部收起”。
- **立即测试 / 开始测试**：弹出确认（“距离测试时间还有 XX，你确认要提前测试吗？……测试期间，联网及 QA bot 功能将被禁用”）。确认后进入测试页：
  1. 选择提交解答的方式：**屏幕输入**（键盘，或平板键盘自带的听写按钮；网站本身不录音、不使用任何语音识别服务）或**写在纸上**（交给督导者扫描上传）；
  2. 点“开始计时”：服务器记录开始和截止时间；
  3. 左边显示题目 PDF，右边答题区（自动保存），可前后切换题目；
  4. “提交全部答案”后不能再修改；**时间到会自动提交已保存的答案**；
  5. 完成后可随时回顾题目、自己的答案、分数。
- 一个学生同一时间只能有一场测试在进行；开始后中途关闭页面可以回来继续，直到截止时间。
- 预定时间到了之后，学生点击才开始，之后不限期（不会自动开始，也没有缺考）。
- **“禁用联网和 QA bot”的实际含义**：测试页只向本站通信，页面里没有视频、问答机器人和外部链接；测试进行中学生页也会隐藏这些内容。网页**无法**阻止学生切换到浏览器的其他标签页或其他应用，所以系统会**记录离开页面的次数和时长**（为打开题目 PDF 而离开的单独统计），督导者能看到。要真正锁定设备，需要平板系统自带的功能（例如 iPad 的“引导式访问”）。

## AI 判分
- **管理员**在 `/admin/ai` 设置：AI 服务商（Anthropic/Claude、OpenAI/GPT、DeepSeek，或任何“OpenAI 兼容”的自定义服务商，如通义千问、Kimi、智谱，需填 https 接口地址）、判分用的模型名、API 密钥（每个服务商各自保存，选中并保存的那个用于判分）、判分系统提示语（可编辑，可恢复默认）。“测试连通性”会用页面上填的（或已保存的）密钥发一个很小的请求，告诉你是否通、用时多久、错在哪里。
- **API 密钥**加密（AES-256-GCM）后存进数据库；加密用的主密钥是服务器上的一个文件（`/var/lib/apdemo/master.key`，权限 600，第一次需要时自动生成），**不在数据库里，也不在每日备份里**。页面和接口永远不会返回已保存的密钥，只显示末 4 位；审计日志只记录“改了哪几项”，不记录密钥和提示语内容。只拿到数据库或备份文件看不到密钥；把数据库恢复到另一台服务器后，需要在 `/admin/ai` 重新填一次密钥。
- **家长/老师**在“答题与评分”里：为每道题上传**判分标准 PDF**（学生看不到、也打不开），选择学生回答的来源（**学生输入的回答文字**，或**回答 PDF**，二选一），点“请求 AI 评分”。系统恰好把这三样发给 AI：① 题目 PDF ② 学生回答（文字或 PDF）③ 判分标准 PDF（外加管理员设定的系统提示语；不发学生的账号名等身份信息）。AI 按判分标准返回 **1–5 的整数评分 + 反馈**，显示在这道题下面；**不会自动写入评分**，家长/老师点“采用此评分”再保存。也可以“为所有题目请求 AI 评分”（逐题进行，缺判分标准或缺学生回答的题目跳过）。
- AI 出错（密钥错误、模型不存在、额度不足、服务忙、超时、拒绝、回答格式不对…）时，会在这道题下面显示可读的错误，不改动任何评分；成功和失败都有记录。每个督导者每小时最多 60 次请求（`AI_MAX_PER_HOUR` 可调），同一道题同时只能有一个请求在进行。
- **隐私**：这三份材料会从你的服务器发送到你选择的 AI 服务商处理（Claude→Anthropic，GPT→OpenAI，DeepSeek→DeepSeek，自定义→你填的地址；这些服务器多在境外），学生的答题内容和题目文件会离开本服务器。请确认你有权这样处理这些材料（尤其是 College Board 的内容），并已告知学生和家长。服务器必须能出站访问所选服务商的接口（443），例如 `api.anthropic.com`、`api.openai.com`、`api.deepseek.com`。
- 各服务商都用 Node 自带的 `fetch` 直接调用，没有安装各家 SDK：Claude 用 Messages API（`anthropic-version: 2026-10-21`，PDF 用 `document` 内容块，`output_config.format` 约束返回 `{score, feedback}`）；GPT 用 Chat Completions（PDF 用 `file` 内容块，`response_format` json_schema）；DeepSeek 和自定义服务商用 Chat Completions，返回格式靠提示语约束并容错解析。
- **PDF 的处理**：Claude、GPT 能直接读 PDF，原样发送；DeepSeek 只能读文字，服务器先用 `unpdf` 提取 PDF 里的文字再发送。**纯扫描图片的 PDF 提取不出文字，会明确提示失败**（建议改用 Claude/GPT，或提供含文字的 PDF）。自定义服务商可勾选“能直接读 PDF”。
- 自定义服务商的接口地址必须是 https 公网地址（不能指向本机/内网，不能带账号密码）。

## 时区
- **每个账号有一个时区**（管理员新建账号时选择，默认温哥华；以后可以修改）。登录后右上角显示“账号名（时区）”，例如 `Nathan（温哥华，时区：-7）`；括号里的数字是当前相对 UTC 的偏移（夏令时会自动变化）。
- **测试时间一律按学生所在时区**：家长/老师填的日期和时间，就是学生那边的当地时间；学生页、测试页、督导者页显示的都是这个当地时间，界面上不再出现“（温哥华时间）”之类的字样。倒计时、自动提交等按精确时刻计算，不受设备时区影响。
- 家长/老师的时区和学生不一致时，新建、修改、重测测试时会出现提醒：“你的时区是 …，学生的时区是 …。请按学生所在时区填写测试日期和时间”。一次选了时区不同的多个学生时，同一个当地时间会分别按各自的时区生效，并有提示。
- 管理员修改学生的时区后，他**还没开始**的测试保持“当地时间”不变（例如当地下午 3 点），对应的精确时刻随之改变；已开始或已完成的测试不变。
- 可选时区在 `server/timezones.js`（中英文城市名 + IANA 名），要增减改那里。

## 账号规则
- 新建账号只需**账号名**和**账号类型**（学生 / 督导者 / 客服），这两项创建后**不能修改**。
- 学生：创建时必须从“科目管理”列表里选择学习科目，**建立后不能修改**（要学别的科目请新建账号，以保证学习数据和评价的连续性）。科目决定学生所在的板块：AP 自学（`/apdemo`）或写作（`/writing`，目前是占位页）。旧账号里已有的科目升级时自动登记并归入 AP 自学；没有科目的旧账号可以设置一次。
- 督导者：可关联多个学生。
- 客服：可关联多个督导者。
- 初始密码由系统生成，只显示一次，用户第一次登录必须自己改密码；管理员也看不到之后的密码。
- 删除账号需要先“停用”，停用的账号可恢复；彻底删除会一并清除它的关联关系。
- 管理员账号只能在服务器上用命令行创建（`deploy/create-admin.sh`），网页上不能创建。

## 写作板块（开发中）
- 阶段 1（已完成）：写作学生账号有“年级”（Pre-K 到 Grade 12）和“监护人同意”记录（管理员创建时必须选年级并勾选同意，系统记录时间和操作人；年级以后可改，同意记录只读）；督导者在 `/supervisor` 里为写作学生设定**写作日程**（每天几点按学生时区、周一到周日的重复、暂停）和**题目库**（每个孩子一份，标题 + 可选提示语；已被孩子写过的题目不能再改或删；剩余少于 3 个时提醒追加，学生列表上显示“题目不足”）。
- 阶段 2（已完成）：孩子的写作页 `/writing`（英文界面）。到了日程时间当天都能写，每天一篇：列出还没写过的全部题目 → 孩子自选 → 写作区（自动保存）→ **“请提建议（Give me some advice）”**：AI 给当前作文按年级打 1–5 分，并用 5W（Who/What/When/Where/Why）提 2–3 个问题 → 孩子回答 → 页面提示“请把你的回答加入到作文中去” → 孩子**自己改写作文**（系统不代写、不自动插入）→ 再请提建议。轮次最少 2、最多 6：第 1 轮不会结束，从第 2 轮起 AI 判定作文 OK 就给出最终分数并结束，第 6 轮一定结束；第 2 轮之后孩子也可以点“我写完了”（作文没改就直接用上一轮分数，改过则再打一次分）。作文比上一轮没有实质变化（少于 1 句话、5 个词或 8 个词的增删）不能再请建议。每轮的分数显示成进展序列；过往记录列出已完成、没写完的和最近 14 天漏写的日子。
- AI：沿用“AI 评分设置”里选的服务商（Claude / GPT / DeepSeek / 自定义），只发文字；每次请提建议只调用一次，打分和提问同时完成；发给 AI 的只有年级（如 “Grade 4”）、题目、轮次、当前作文和上一轮作文与分数，不含用户名。默认的建议提示语在 `server/settings.js`（`DEFAULT_WRITING_PROMPT`），管理员编辑界面和年级标准表在阶段 3 做。
- 阶段 3（已完成）：管理员新页面 `/admin/writing`（导航“写作设置”）：① **建议提示语**可编辑、可恢复默认；② **各年级的写作期望**（Pre-K 到 Grade 12，共 14 条，默认内容已起草，可逐条修改，清空即恢复默认），每次调用只把孩子所在年级的那一条发给 AI，作为评分的尺度；③ **最近 30 天的 AI 用量**（篇数、调用次数、token、按学生统计、AI 标记的安全内容、失败次数）。每一轮记录模型、服务商、token 和安全标记；AI 标记了安全内容时，孩子会看到一条固定的温和提示（找信任的大人聊聊），督导者页的标记和回看在阶段 4。
- 数据库版本 9（每一轮增加用量和安全标记字段）；版本 8 的写作表（作文、每一轮、最终评分、安全标记）在阶段 2 开始使用。
- 方案见内部文档；后续阶段：孩子的写作页 → AI“请提建议”循环和评分 → 督导者回看与改分。

## 运行测试
需要 Node.js。测试依赖只在开发时用；运行时只依赖 unpdf。
```bash
npm install
npx playwright install webkit      # 首次需要；Linux 上缺系统库时再运行 npx playwright install-deps webkit
```
